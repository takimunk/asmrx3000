# Нейро-синтез звуков источников — выбор стека

> Статус (2026-10-18): **одна общая мультивидовая модель птиц + маленький адаптер на вид**.
> Встроены 5 видов (зяблик, зарянка, певчий дрозд, соловей — в базе; чёрный дрозд — новый вид
> через адаптер), включаются параметром `NEURAL_BIRDS` (по умолчанию 1 — и в приложении, и в
> вебе). Остальные 7 видов сцены пока процедурные, почему и что нужно — §7.9. Большие предобученные модели (Perch)
> используются только офлайн — для оценки качества.
> Результаты обучения и замеры — в разделе 7. Принцип из SPEC §3 не меняется: **никаких
> проигрываемых дорожек**. Каждая модель — маленький управляемый синтезатор, который движок
> вызывает в аудио-потоке и размещает в 3D. Сгенерированные чужими сервисами звуки (ElevenLabs
> и т.п.) допустимы только как обучающие данные, и только с согласия пользователя.

## 1. Требования, которые определяют выбор

| Требование | Следствие |
|---|---|
| Real-time на CPU, десятки голосов одновременно | бюджет ≪ 1 % ядра на голос → модель ~10⁴–10⁵ параметров, работа на кадрах (200 Гц), а не на сэмплах |
| Портируемость: macOS → Win/Linux → WASM в AudioWorklet | чистый Rust без C++-рантаймов и без потоков; нет аллокаций в аудио-потоке |
| Управляемость (директор сцены решает, когда и что поёт птица) | явные контролы: f0, громкость, «усилие», темп; новые фразы генерируются, а не выбираются из записей |
| Мало чистых данных (десятки записей на вид, шум леса, ветер) | сильный индуктивный bias (DSP-синтезатор внутри модели), а не «чёрный ящик» на сэмплах |
| Бинарь для Chrome-расширения | веса и код инференса — сотни КБ, не десятки МБ |

## 2. Семейства моделей

| Семейство | Как работает | Параметры / цена | Управляемость | Вердикт |
|---|---|---|---|---|
| **DDSP** (Engel et al., 2020): гармонический осциллятор + фильтрованный шум, сеть предсказывает амплитуды гармоник и спектр шума по кадрам | f0 и громкость — входы, тембр — выход сети | 10⁴–10⁶, кадровая частота 100–250 Гц → микросекунды на кадр | полная: f0, громкость, любые доп. контролы | **берём** для голосов птиц |
| RAVE (Caillon & Esling, 2021) | VAE на волне с PQMF, латент 48 кГц/2048 | ~17 М параметров, conv-стек на каждый блок; на CPU ~5–20 % ядра на голос | только латент (неинтерпретируемый) | слишком тяжёлый и неуправляемый для десятков птиц; оставить на будущее для «текстур» |
| Neural source-filter (NSF, Wang 2019) | синус-источник по f0 + нейро-фильтр на сэмплах | 10⁵–10⁶, но **на каждом сэмпле** | хорошая по f0 | дороже DDSP в ~100× при том же контроле |
| WaveRNN / LPCNet / FastGRU-вокодеры | авторегрессия по сэмплам | 1–3 GFLOP/с на голос | через мел/признаки | дорого для 30 голосов, плохо для WASM |
| Нейро-текстуры для стационарных звуков (статистики Мак-Дермотта, DDSP-noise, нейросетевые «grain»-модели) | генерация шума с заданной статистикой спектра/модуляций | 10³–10⁴ | средняя (параметры потока) | вода и ветер уже физические (Миннарт, поле порывов); нейро-«доводчик» — только если A/B покажет, что физики не хватает (§6) |
| Синтаксис песни: маленький GRU / трансформер над токенами слогов | языковая модель по последовательностям слогов | 10⁴–10⁵, вызывается раз на слог | температура, длина фразы, «репертуар» | **берём** GRU (дешевле трансформера при потоковой генерации, состояние = 1 вектор) |

### 2.1 Итоговая архитектура: общая база + адаптеры видов

```
 директор сцены ──► activity, pitch, tempo, effort, loudness, variation
                        │
   [1] Синтаксис (общий GRU 48 над 64 токенами слогов + эмбеддинг вида) — раз на слог:
        какой слог следующий, пауза перед ним, конец песни
                        │ токен
   [2] Декодер контуров (общий CVAE-декодер: [токен, вид, z] → слог) — раз на слог:
        f0(t), громкость(t), «усилие»(t), длительность; z ~ N(0, variation)
                        │ кадровые контролы (5 мс)
   [3] DDSP-голос (общий: GRU 96 + MLP, вход [f0, громкость, усилие, эмбеддинг вида]) — раз на кадр:
        амплитуды 8 гармоник + усиления 20 шумовых полос
                        │
        синтез на каждом сэмпле: аддитивный осциллятор + банк полосовых биквадов → моно → engine.rs
```

**Что общее, что видовое.** Все веса — общие (`birds_base.asnw`, 109 тыс. параметров, 214 КиБ
f16). Вид — это адаптер (`<вид>.asna`): эмбеддинг голоса (16 чисел), нормировка входов (4),
эмбеддинг синтаксиса (8) + сдвиг логитов токенов (65), эмбеддинг декодера контуров (8) и пара
констант. Это ~100 чисел, **694 байта**. Для нового вида, которого не было в базе, к этому
добавляется LoRA ранга 4 на выходные слои голоса (1 600 чисел, **7 КБ**).

**Почему это ничего не стоит в рантайме.** Эмбеддинг вида входит в сеть только линейно
(конкатенацией ко входу слоя), поэтому для фиксированного вида
`W·[x; e] + b = W_x·x + (b + W_e·e)`, а LoRA вливается в вес: `W + B·A`. При загрузке
`core/src/neural/compose.rs` сворачивает адаптер в обычные веса — в аудио-потоке работает та же
маленькая сеть, что была бы у отдельной модели вида. Тесты сверяют результат с PyTorch.

**Новый вид = минуты.** База заморожена, учатся только эмбеддинги (+ LoRA): голос — 1 500 шагов,
1.8 мин на MPS; синтаксис и контуры — меньше минуты на CPU. Проверено на чёрном дрозде, которого
не было в базе (§7.3): адаптер не хуже отдельной модели, обученной с нуля за 24 мин.

**Как было раньше** (первая итерация, в истории git): по отдельной модели на вид (75 тыс.
параметров, 239 КиБ) и банк реальных слогов-образцов на токен. Общая база с 4 видами в сумме
меньше и на отложенных данных в среднем не хуже (§7.2).

Почему вообще трёхуровневая схема, а не «одна сеть генерирует звук»:
- голос [3] обучается как автоэнкодер на реальных записях (контролы → звук) и не знает про песню;
  [1]–[2] обучаются на разметке слогов;
- каждый уровень управляем: директор может попросить «громче, выше, реже, разнообразнее»;
- новизна: фраза собирается из сэмплированных токенов и контуров, а не копирует запись.

Вывод по пункту «RAVE как база»: для голосов птиц наша DDSP-база уже укладывается в
0.15 % ядра на голос; RAVE-семейство и по цене, и по лицензии подходит максимум как офлайн-учитель
для текстур — и то только после решения по NC. Для текстур первым кандидатом в учителя/
перцептивную потерю берём DAC (MIT).

**Синтезатор шума — банк биквадов, а не FFT-фильтр как в оригинальном DDSP.** В оригинале
шум фильтруется частотной выборкой FIR через FFT на каждый кадр. Мы используем фиксированный
банк из 24 полосовых фильтров (лог-шкала 1–16 кГц) с переменными усилениями: одна и та же
схема в PyTorch (при обучении) и в Rust, центры полос заданы в Гц, поэтому голос работает
на любой частоте дискретизации движка (44.1/48 кГц). Цена ~24 биквада на сэмпл.

## 4. Инференс внутри движка

| Вариант | Цена кадра для нашей модели | Размер | WASM (AudioWorklet) | Аллокации / RT-безопасность |
|---|---|---|---|---|
| **Свой минимальный Rust** (Linear, GRU, активации; `[f32]` буферы, заранее выделенные) | ~10–20 мкс (60 k MAC), без накладных расходов на диспетчеризацию | ~10 КБ кода + веса | да, тот же код (`wasm32-unknown-unknown`, опционально SIMD128) | ноль аллокаций в `render`, нет потоков |
| candle (HF) | тензорный граф, накладные расходы на операцию ≫ сама операция для 64×64 | +несколько МБ, много зависимостей | да, но тяжело; потоков в AudioWorklet нет | аллоцирует тензоры на каждый вызов |
| tract (Sonos, ONNX/NNEF) | хорош для conv, потоковый GRU со стейтом — неудобно; оверхед на вызов | ~2–5 МБ | да | аллокации в `run`, нужен прогрев/пулы |
| ONNX Runtime | быстрый на больших моделях | 10–30 МБ C++ | только onnxruntime-web (JS/WASM отдельно от нашего Rust-ядра) | нет гарантий RT, C++ рантайм |

**Решение: свой минимальный инференс на Rust** (`core/src/neural/`). Модели крошечные и состоят
из 3–4 типов слоёв; фреймворк дал бы только оверхед, мегабайты и аллокации, но ни одной
нужной возможности. Код без зависимостей и без `unsafe`, совместим с WASM, считается
детерминированно (одинаковые веса → одинаковый звук на всех платформах, что важно для
офлайн-рендера и тестов). Если когда-нибудь понадобится большая модель (RAVE-текстуры),
пересмотрим: tract для офлайн-инструментов, но не в аудио-потоке.

### 4.1 Формат весов `ASNW` (asmr neural weights)

```
magic  "ASNW"            4 байта
version u32 LE           сейчас 1
count   u32 LE           число тензоров
повторить count раз:
  name_len u16, name (utf-8)
  dtype   u8             0 = f32, 1 = f16
  ndim    u8, dims u32 × ndim
  data    LE, row-major
```

Конфигурация хранится там же — как именованные тензоры (`cfg.hop_s`, `cfg.band_centers`, …).
Два вида файлов в одном контейнере:

| Файл | Содержимое | Размер |
|---|---|---|
| `birds_base.asnw` | общие веса (`voice.*`, `song.*`, `contour.*`, f16), общий конфиг, `cfg.base_id` (хеш весов) | 214 КиБ |
| `<вид>.asna` | `adapter.voice.emb`, `cfg.voice_norm`, `adapter.song.emb`, `adapter.song.bias`, `adapter.contour.emb`, опционально `adapter.voice.lora{1,2}.{A,B}`, видовые константы (`cfg.silence_db`, `cfg.reuse`, …), `cfg.base_id` | 0.7 КБ (7 КБ с LoRA) |

Адаптер помнит `base_id` своей базы — загрузчик откажется собирать адаптер с чужой базой.
Экспорт: `ml/asmr_ml/export_multi.py`; загрузка: `weights.rs` → `compose.rs` → обычные
`VoiceModel`/`SongModel`. API: `neural::builtin("robin")` (встроенные) или
`neural::load_adapter(bytes)` (адаптер, полученный позже — например, скачанный).

## 6. Вода/ветер: физика или нейро-текстура

Вода (Миннарт) и ветер (поле порывов) уже физические и управляемые. Нейро-текстура
оправдана только если A/B-прослушивание против реальных записей ручья покажет
неустранимую разницу. План сравнения: те же метрики, что для птиц (MR-STFT расстояние
и расстояние статистик модуляционного спектра по Мак-Дермотту) между записью ручья,
физической моделью и DDSP-noise-моделью (только шумовая ветка, контролы = скорость потока).
Требует записей ручьёв (Freesound CC0/BY → нужен ключ).

### 7.5 Perch 2.0 как метрика качества

`uv run python -m asmr_ml.quality <вид>`: окна по 5 с; «узнал» — доля окон, где целевой вид
на 1-м месте среди 14 795 классов Perch; «ранг» — медианный ранг вида; «близость» — косинус
среднего эмбеддинга набора к среднему эмбеддингу реальных записей.

| Вид | реальные: узнал / ранг | **ресинтез** (база+адаптер): узнал / ранг / близость | **генерация** (Rust): узнал / ранг / близость | другие виды: ранг / близость |
|---|---|---|---|---|
| зяблик | 60 % / 1 | 40 % / 2.5 / 0.59 | 0 % / 35 / 0.22 | 9.5 / 0.60 |
| зарянка | 80 % / 1 | 77 % / 1 / 0.79 | **69 % / 1 / 0.58** | 13.5 / 0.52 |
| певчий дрозд | 100 % / 1 | 50 % / 1.5 / 0.66 | 6 % / 30 / 0.25 | 14 / 0.40 |
| соловей | 100 % / 1 | 75 % / 1 / 0.69 | 0 % / 58 / 0.23 | 53 / 0.47 |
| чёрный дрозд (адаптер) | 92 % / 1 | 38 % / 9 / 0.42 | 0 % / 18.5 / 0.22 | 10.5 / 0.55 |

Честный вывод: **голос** (ресинтез) Perch узнаёт как нужный вид — модель тембра работает.
**Генерация новых песен** пока узнаётся только у зарянки: у остальных видов генерируемая
фраза дальше от вида, чем записи *других* видов. Причины видны на спектрограммах: декодер
контуров сглаживает быстрые свипы (зяблик) в ровные тоны, паузы между слогами слишком
короткие, а токены — «полуслоги» (§9.1). Теперь это измеряемо: Perch — целевая метрика для
следующей итерации генерации.

- `cargo check --target wasm32-unknown-unknown` проходит.

### 7.8 Интеграция с движком (для директора)

```rust
let model = asmr_core::neural::builtin("robin").unwrap();   // при сборке сцены (сворачивает адаптер)
// или: asmr_core::neural::load_adapter(&bytes)?           // адаптер, полученный позже
let mut bird = NeuralBird::new(model, sample_rate, seed);
bird.render(&mut out, &BirdControls { activity, pitch, tempo, effort, loudness, variation }); // аудио-поток
bird.freq(); bird.is_singing();                               // телеметрия
```

В движке птицы приходят из графа сцены директора: `core/src/director/voices.rs::bird_voice`
берёт `neural::builtin(<вид>)`, если у вида есть модель (`neural_model_name()`), иначе —
процедурный голос; короткие полётные, контактные и тревожные позывки всегда процедурные.
Параметр `NEURAL_BIRDS` (`ASMR_PARAM_NEURAL_BIRDS = 10`, по умолчанию 1: `Engine::with_scene`
ставит его сам, macOS-оболочка его не меняет, веб-ворклет тоже) переключает
нейро/процедурные голоса. Чёрный дрозд — `Species::Blackbird`, в сцене по умолчанию их два
(уровень нейро-голоса подогнан к процедурному: `neural_trim_db` = 13.1 дБ, `examples/calibrate.rs`).

Директор управляет голосом через `BirdControls`: `activity` (пауза до следующей песни
пересчитывается сразу — птица, которую попросили ответить соседу, не дослушивает старую
паузу), `wait` (сосед поёт — не начинать) и `NeuralBird::hurry(s)` (ответить в ближайшие
`s` секунд). Подробно — docs/director.md, «Жизнь птиц».

### 7.9 Покрытие видов (2026-10-18)

| Вид | Песня | Почему так |
|---|---|---|
| зяблик, зарянка, певчий дрозд, соловей | **нейро** (база) | |
| чёрный дрозд | **нейро** (адаптер + LoRA) | |

| чайка | процедурный | нет записей; f0 ~1 кГц с сильными гармониками (8 гармоник базы хватает до ~8 кГц), шумовой банк снизу обрезан |

Локально есть только данные первых пяти видов (`ml/data` в рабочей копии `neural-sound`:
220 записей Commons). Обучение остальных в этой итерации не запускалось: записи надо сначала
скачать (Wikimedia Commons, без ключа, `asmr_ml.data.commons`; это загрузка ~0.5–1 ГБ, на неё
нужно согласие пользователя), а для низкоголосых видов ещё и переучить базу.

Что нужно, по шагам:
1. **Ласточка, жаворонок** (минуты на вид): добавить в `ml/asmr_ml/species.py`
   (`Hirundo rustica` 2000–9000 Гц, `Alauda arvensis` 1500–8000 Гц), скачать
   (`uv run python -m asmr_ml.data.commons`), `prep`, `multi adapt <вид> --rank 4`,
   `multisong adapt <вид>`, `export_multi --adapter <вид>`; строка в `BUILTIN`
   (`core/src/neural/mod.rs`) и в `neural_model_name()`; `examples/calibrate.rs` → `neural_trim_db`.
   Ласточка и жаворонок поют в полёте — нейро-голос подойдёт и для `SongFlight`/`Hawking`.
2. **Неясыть, кукушка, вяхирь, ворон, чайка**: расширить базу вниз (`BAND_LO` ~150 Гц, f0 от
   250 Гц, возможно 12 гармоник), переучить базу на всех видах (~40 мин MPS) и заново
   экспортировать все адаптеры (parity-тесты в Rust это проверят). Записи: Commons
   (`Strix aluco`, `Cuculus canorus`, `Columba palumbus`, `Corvus corax`, `Larus argentatus`);
   у ворона и чайки голоса шумные — проверить, что DDSP-шумовая ветка их держит (MR-STFT против
   синусоиды, Perch-узнаваемость).
3. До тех пор процедурные голоса улучшены: у неясыти дрожащее «у-у-у» перед длинным уханьем и
   «кэ-вик» самки, у кукушки «ку-ку-ку» и усталое понижение серии, у вяхиря завершающее «кук»,
   у ласточки скрипучая трель в конце, новые голоса жаворонка (непрерывный поток трелей),
   чайки («а-ау» и хохочущая серия, носовой тембр: гармоники 2–4 и шероховатость) и ворона
   (хриплое «крук» с амплитудной модуляцией 55 Гц и глухое «клонг»); у всех — тревожные крики.

## 8. Открытые вопросы для пользователя

1. **NC-данные.** Учить ли на CC BY-NC записях xeno-canto/BirdCLEF (в разы больше данных)?
   Если продукт будет платным — нет.
2. **BirdNET** (веса CC BY-NC-SA 4.0): разрешаем ли как офлайн-инструмент для сегментации
   данных? В движок он не попадёт в любом случае. Без него сегментация — наша (энергия + f0).
3. **RAVE / BRAVE** (CC BY-NC 4.0, включая код): не используем. Нужен ли пересмотр — только если
   продукт некоммерческий.
4. **BY-SA и веса.** Считаем ли веса, обученные на CC BY-SA записях, производным
   произведением (тогда веса — под BY-SA с атрибуцией)? Консервативно: да, публикуем
   атрибуцию из манифеста.
5. **Ключи**: xeno-canto API v3 (`ml/.env`: `XC_API_KEY=`), Freesound (`FREESOUND_API_KEY=`) —
   больше данных и записи ручьёв/ветра для текстур.
6. **ElevenLabs** — пока не нужен.

## 9. Что дальше (технически)

1. **Генерация фраз — главный пробел (§7.5).** Сегментация слогов по огибающей с порогом
   относительно локального максимума (а не по скачкам f0) → токены = целые слоги; токенизация
   по DTW; условие синтаксиса на позицию в песне (у зяблика трель → росчерк); декодер контуров
   с более «острым» выходом (меньше β в CVAE или обучение на f0-производных). Целевые метрики —
   Perch «узнал» и близость к реальным записям; цель — уровень ресинтеза.
2. **Perch-эмбеддинг вида как условие.** Сейчас эмбеддинги вида учатся с нуля. Можно
   инициализировать их проекцией среднего Perch-эмбеддинга вида — тогда адаптер нового вида
   стартует не с «среднего вида», а с акустически близкого.
3. **Двухголосие сиринкса** (дрозды, соловей): второй гармонический осциллятор со своим f0.
4. **Шум записей в голосе:** более строгий гейт, больше чистых записей (xeno-canto, качество A).
5. **Текстуры (вода, ветер, листва):** нужны записи (Freesound). Тогда — сравнение Миннарта с
   DDSP-noise; DAC (MIT) — офлайн-учитель / перцептивная потеря.
