# Нейро-синтез звуков источников — выбор стека

> Статус (2026-10-18): стек выбран и установлен; обучены 4 вида (зяблик, зарянка, певчий дрозд,
> соловей), все встроены в `asmr-core` и включаются параметром `NEURAL_BIRDS`.
> Результаты обучения и замеры — в разделе 7. Принцип из SPEC §3 не меняется: **никаких
> проигрываемых дорожек**. Каждая модель — маленький управляемый синтезатор, который движок
> вызывает в аудио-потоке и размещает в 3D. Сгенерированные чужими сервисами звуки (ElevenLabs
> и т.п.) допустимы только как обучающие данные, и только с согласия пользователя.

## 1. Требования, которые определяют выбор

| Требование | Следствие |
|---|---|
| Real-time на CPU, десятки голосов одновременно | бюджет ≪ 1 % ядра на голос → модель ~10⁴–10⁵ параметров, работа на кадрах (200 Гц), а не на сэмплах |
| Портируемость: macOS → Win/Linux → WASM в AudioWorklet | чистый Rust без C++-рантаймов и без потоков; нет аллокаций в аудио-потоке |
| Управляемость (директор сцены решает, когда и что поёт птица) | явные контролы: f0, громкость, «усилие», темп; новые фразы генерируются, а не выбираются из записей |
| Мало чистых данных (десятки записей на вид, шум леса, ветер) | сильный индуктивный bias (DSP-синтезатор внутри модели), а не «чёрный ящик» на сэмплах |
| Бинарь для Chrome-расширения | веса и код инференса — сотни КБ, не десятки МБ |

## 2. Семейства моделей

| Семейство | Как работает | Параметры / цена | Управляемость | Вердикт |
|---|---|---|---|---|
| **DDSP** (Engel et al., 2020): гармонический осциллятор + фильтрованный шум, сеть предсказывает амплитуды гармоник и спектр шума по кадрам | f0 и громкость — входы, тембр — выход сети | 10⁴–10⁶, кадровая частота 100–250 Гц → микросекунды на кадр | полная: f0, громкость, любые доп. контролы | **берём** для голосов птиц |
| RAVE (Caillon & Esling, 2021) | VAE на волне с PQMF, латент 48 кГц/2048 | ~17 М параметров, conv-стек на каждый блок; на CPU ~5–20 % ядра на голос | только латент (неинтерпретируемый) | слишком тяжёлый и неуправляемый для десятков птиц; оставить на будущее для «текстур» |
| Neural source-filter (NSF, Wang 2019) | синус-источник по f0 + нейро-фильтр на сэмплах | 10⁵–10⁶, но **на каждом сэмпле** | хорошая по f0 | дороже DDSP в ~100× при том же контроле |
| WaveRNN / LPCNet / FastGRU-вокодеры | авторегрессия по сэмплам | 1–3 GFLOP/с на голос | через мел/признаки | дорого для 30 голосов, плохо для WASM |
| Нейро-текстуры для стационарных звуков (статистики Мак-Дермотта, DDSP-noise, нейросетевые «grain»-модели) | генерация шума с заданной статистикой спектра/модуляций | 10³–10⁴ | средняя (параметры потока) | вода и ветер уже физические (Миннарт, поле порывов); нейро-«доводчик» — только если A/B покажет, что физики не хватает (§6) |
| Синтаксис песни: маленький GRU / трансформер над токенами слогов | языковая модель по последовательностям слогов | 10⁴–10⁵, вызывается раз на слог | температура, длина фразы, «репертуар» | **берём** GRU (дешевле трансформера при потоковой генерации, состояние = 1 вектор) |

### 2.1 Итоговая архитектура голоса птицы (3 уровня)

```
 директор сцены ──► activity, effort, pitch, tempo
                        │
   [1] SongModel (GRU над токенами слогов, ~20 k парам.) — раз на слог:
        какой слог следующий, пауза перед ним, конец фразы
                        │ токен
   [2] ContourModel (на кластер слога: средний контур + PCA-моды разброса)
        → f0(t), loudness(t), длительность слога   (кадры по 5 мс)
                        │ кадровые контролы
   [3] DdspVoice (GRU 64 + MLP, ~60 k парам.) — раз на кадр (200 Гц):
        амплитуды N гармоник + усиления 24 шумовых полос
                        │
        синтез на каждом сэмпле: аддитивный осциллятор (фаза по f0, интерполяция амплитуд)
        + банк полосовых биквадов на белом шуме → моно-сигнал → engine.rs (3D)
```

Почему так, а не «одна сеть генерирует звук»:
- уровень [3] обучается как автоэнкодер на реальных записях (f0/громкость/усилие → звук),
  ему не нужно знать про песню; уровень [1]–[2] обучаются отдельно на разметке слогов;
- каждый уровень остаётся интерпретируемым и управляемым: директор может попросить
  «поёт громче, выше, реже», не переобучая модель;
- новизна: фраза собирается из сэмплированных токенов и сэмплированных контуров, которые
  никогда не повторяют обучающую запись дословно.

**Синтезатор шума — банк биквадов, а не FFT-фильтр как в оригинальном DDSP.** В оригинале
шум фильтруется частотной выборкой FIR через FFT на каждый кадр. Мы используем фиксированный
банк из 24 полосовых фильтров (лог-шкала 1–16 кГц) с переменными усилениями: одна и та же
схема в PyTorch (при обучении) и в Rust, центры полос заданы в Гц, поэтому голос работает
на любой частоте дискретизации движка (44.1/48 кГц). Цена ~24 биквада на сэмпл.

## 3. Обучающий стек (Apple Silicon)

| Задача | Выбор | Почему / альтернатива |
|---|---|---|
| Окружение | `uv` + Python 3.12, `ml/pyproject.toml` + `uv.lock` | воспроизводимо, быстро; conda не нужна |
| Обучение | PyTorch 2.x + **MPS** (M5 Max) | проверено: MPS доступен, ~7–8 TFLOPS fp32 на matmul. Модели крошечные, узкое место — I/O и синтез, не GPU |
| Аудио I/O | `soundfile` (libsndfile: wav/flac/ogg/mp3), `librosa` (ресемплинг, pYIN) | torchaudio используем минимально — его I/O в последних версиях вынесен в torchcodec |
| f0 птиц | **собственный трекер доминантной частоты** (STFT 2048 @ 48 кГц, параболическая интерполяция, проверка субгармоник, сглаживание медианой) + pYIN как контроль | CREPE/torchcrepe обучен на голосе/музыке и ограничен ~2 кГц — песня птиц 2–9 кГц, вне диапазона. torchcrepe установлен, но для птиц не используется |
| Детекция вида / сегментация | энергетический детектор слогов + полосовой SNR; **BirdNET** (Kahl et al.) — опционально | BirdNET-Analyzer тянет TensorFlow/TFLite (лицензия моделей CC BY-NC-SA 4.0). Для старта: записи уже размечены по виду (xeno-canto/Commons), мы отбираем по SNR и полосе. BirdNET подключим, когда понадобится чистить смешанные записи (несколько видов в одной) |
| Денойз | спектральный гейт (профиль шума по тихим кадрам записи) | простой, предсказуемый; noisereduce/Demucs не нужны |
| Признаки | f0 (Гц), loudness (A-взвешенная, дБ), effort = спектральная «яркость» относительно f0 | всё кадрами по 5 мс (hop 240 @ 48 кГц) |
| Потери | multi-resolution STFT (лог + линейные магнитуды, окна 256…4096) | стандарт DDSP |

## 4. Инференс внутри движка

| Вариант | Цена кадра для нашей модели | Размер | WASM (AudioWorklet) | Аллокации / RT-безопасность |
|---|---|---|---|---|
| **Свой минимальный Rust** (Linear, GRU, активации; `[f32]` буферы, заранее выделенные) | ~10–20 мкс (60 k MAC), без накладных расходов на диспетчеризацию | ~10 КБ кода + веса | да, тот же код (`wasm32-unknown-unknown`, опционально SIMD128) | ноль аллокаций в `render`, нет потоков |
| candle (HF) | тензорный граф, накладные расходы на операцию ≫ сама операция для 64×64 | +несколько МБ, много зависимостей | да, но тяжело; потоков в AudioWorklet нет | аллоцирует тензоры на каждый вызов |
| tract (Sonos, ONNX/NNEF) | хорош для conv, потоковый GRU со стейтом — неудобно; оверхед на вызов | ~2–5 МБ | да | аллокации в `run`, нужен прогрев/пулы |
| ONNX Runtime | быстрый на больших моделях | 10–30 МБ C++ | только onnxruntime-web (JS/WASM отдельно от нашего Rust-ядра) | нет гарантий RT, C++ рантайм |

**Решение: свой минимальный инференс на Rust** (`core/src/neural/`). Модели крошечные и состоят
из 3–4 типов слоёв; фреймворк дал бы только оверхед, мегабайты и аллокации, но ни одной
нужной возможности. Код без зависимостей и без `unsafe`, совместим с WASM, считается
детерминированно (одинаковые веса → одинаковый звук на всех платформах, что важно для
офлайн-рендера и тестов). Если когда-нибудь понадобится большая модель (RAVE-текстуры),
пересмотрим: tract для офлайн-инструментов, но не в аудио-потоке.

### 4.1 Формат весов `ASNW` (asmr neural weights)

```
magic  "ASNW"            4 байта
version u32 LE           сейчас 1
count   u32 LE           число тензоров
повторить count раз:
  name_len u16, name (utf-8)
  dtype   u8             0 = f32, 1 = f16
  ndim    u8, dims u32 × ndim
  data    LE, row-major
```

Конфигурация (частота кадров, число гармоник, центры полос, нормировка входов, словарь
слогов, контуры) хранится там же — как именованные тензоры (`cfg.hop_s`, `noise.centers_hz`,
…). Один файл = один вид, ~100–300 КБ (f16). Экспорт: `ml/asmr_ml/export.py`, загрузка:
`core/src/neural/weights.rs`. Версия формата поднимается при несовместимых изменениях;
загрузчик проверяет имена и формы тензоров и отказывается, если что-то не сходится.

## 6. Вода/ветер: физика или нейро-текстура

Вода (Миннарт) и ветер (поле порывов) уже физические и управляемые. Нейро-текстура
оправдана только если A/B-прослушивание против реальных записей ручья покажет
неустранимую разницу. План сравнения: те же метрики, что для птиц (MR-STFT расстояние
и расстояние статистик модуляционного спектра по Мак-Дермотту) между записью ручья,
физической моделью и DDSP-noise-моделью (только шумовая ветка, контролы = скорость потока).
Требует записей ручьёв (Freesound CC0/BY → нужен ключ).

анализом синтезированного звука тем же трекером.

### 7.4 Rust: размер и CPU (M5 Max, один поток, 48 кГц)

- Вес на вид: 239 КиБ (`.asnw`, f16), 75 200 параметров (голос + синтаксис) + банк контуров.
- Совпадение с PyTorch: относительная ошибка выходов сети < 1e-3 (`neural::voice::tests::matches_pytorch`).
- `cargo run --release --example neural_bench -- robin`: сеть 5.2 мкс на кадр (0.10 % ядра),
  синтез (8 гармоник + 20 биквадов) 0.09 % → **0.19 % ядра на голос во время пения**.
- `neural_bird -- chaffinch 60 x.wav 8` (8 голосов, блоки по 256): **0.12 % ядра на голос в среднем**,
  0.25 % во время пения (птица поёт ~45 % времени, молчащий голос ≈ 0).
- Сцена целиком (`render -- 60 out.wav neural`): DSP-нагрузка 2.2 % против 1.8 % с процедурными птицами.
- `cargo check --target wasm32-unknown-unknown` проходит (ноль зависимостей, нет `unsafe`, нет потоков).

### 7.5 Как слушать

`ml/out/listen/<вид>/` (`uv run python -m asmr_ml.listen <вид>`): `1_real.wav` (отложенная
запись), `2_resynth.wav` (голос по контролам из неё), `3_generated.wav` (Rust: новые песни из
модели синтаксиса), `sheet.png` — спектрограммы. Сцена: `ml/out/listen/scene_{neural,procedural}.wav`.

Что слышно: ресинтез близок к оригиналу (свипы зяблика, трели и высокие ноты зарянки); новые песни
звучат видоправдоподобно по ритму и регистру, но фразовая структура (у зяблика: трель → росчерк)
ещё размыта — см. §8.

### 7.6 Интеграция с движком (для директора)

```rust
let model = asmr_core::neural::builtin("robin").unwrap();          // при сборке сцены
let mut bird = NeuralBird::new(model, sample_rate, seed);
bird.render(&mut out, &BirdControls { activity, pitch, tempo, effort, loudness, variation }); // аудио-поток
bird.freq(); bird.is_singing();                                      // телеметрия
```

Сейчас в `engine.rs` минимальный хук: у слота птицы рядом с процедурным голосом лежит
`Option<NeuralBird>`, параметр `NEURAL_BIRDS` (C ABI: `ASMR_PARAM_NEURAL_BIRDS = 9`, по умолчанию 0)
выбирает, какой из них звучит. Первая птица — зяблик, вторая — зарянка.

## 8. Открытые вопросы для пользователя

1. **NC-данные.** Учить ли на CC BY-NC записях xeno-canto/BirdCLEF (в разы больше данных)?
   Если продукт будет платным — нет.
2. **BY-SA и веса.** Считаем ли веса, обученные на CC BY-SA записях, производным
   произведением (тогда веса — под BY-SA с атрибуцией)? Консервативно: да, публикуем
   атрибуцию из манифеста.
3. **Ключи**: xeno-canto API v3, Freesound — расширят данные и дадут записи ручьёв.
4. **ElevenLabs** — нужен ли вообще; для птиц, скорее всего, нет (реальных записей хватает).

## 9. Что дальше (технически)

1. **Фразовая структура.** Сегментатор режет слог зяблика на 2–3 части (по скачкам f0), поэтому
   токены — «полуслоги», и GRU учит циклы токенов, а не фразы. Следующий шаг: сегментация по
   огибающей с порогом относительно локального максимума + токенизация по DTW-расстоянию, и
   условие GRU на позицию в песне (трель → росчерк у зяблика).
2. **Двухголосие сиринкса** (певчий дрозд, соловей): модель моно-f0 не передаёт два независимых
   тона. Вариант: второй гармонический осциллятор со своим f0 (трекер двух пиков).
3. **Шум записей в голосе.** Шумовая ветка частично выучила фон записей (лёгкая «дымка» в
   ресинтезе). Помогут более строгий гейт и больше чистых записей (xeno-canto качество A).
4. **Вода.** Нужны записи ручьёв (Freesound, ключ) для сравнения Миннарта с DDSP-noise.
5. Чёрный дрозд: голос обучен по тем же скриптам, экспорт и встраивание — одна команда.
