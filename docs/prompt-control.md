# Управление промптом

Пользователь пишет в поповере просьбу обычными словами («поспокойнее», «ночь, лёгкий дождь стихает», «как будто у водопада»). Языковая модель получает просьбу и **текущее состояние** и возвращает набор изменений параметров. Движок плавно ведёт к ним значения. Ползунки остаются: промпт — ещё один способ ими управлять, на том же словаре.

![поле промпта](img/prompt-control.png)

## Поток

```
текст ─► PromptRequest (system + context + state + tool schema из ядра)
      ─► PromptProvider.complete()  (адаптер провайдера, HTTP)
      ─► PromptReply (вход инструмента = патч + explanation)
      ─► asmr_apply_patch_json ─► плавные переходы + undo-патч (⌘Z)
```

Всё, что видит модель, строит ядро (`core/src/prompt.rs`), поэтому адаптер только переносит данные и тестируется вместе с ядром.

## ABI (core/include/asmr.h)

Все три функции можно вызывать из любого потока. Вход и выход — JSON в UTF-8. Функция пишет результат с завершающим NUL в `out`, только если `max` больше его длины, а возвращает длину в любом случае: сначала вызовите с `out = NULL`, чтобы узнать размер буфера.

| Функция | Что делает |
|---|---|
| `asmr_get_state_json` | `controls`: `key`, `group`, `macro` или `parent`, `value`, `min`/`max`, `log`, `unit`, `default`, `overridden`; у пресетов ещё `option` и `options`. `environment`: идёт ли звук, дождь сейчас, мокрость листвы, грунт, реверберация. `objects`: `id`, `kind`, `pos`, `movable`, `moving`. Плюс `frame` (система координат) и `gliding` (сколько переходов идёт сейчас). |
| `asmr_apply_patch_json` | Применяет патч и возвращает результат: `ok`, `applied` (`key`, итоговое `value`, `clamped`), `moved`, `errors`, `undo`. |
| `asmr_get_prompt_json` | `system` — статический промпт, его можно кэшировать. `context` — текущие значения текстом. `tool` — `set_scene` и его `input_schema`. |

### Патч

```json
{"glide_s": 4,
 "changes": [{"key": "water.flow", "value": 0.3},
             {"key": "water.regime", "value": "rapids"},
             {"key": "water.depth", "value": "reset"},
             {"key": "rain.rate", "value": 0.2, "glide_s": 30}],
 "moves": [{"object": 3, "position": [4, 6, 0]}]}
```

* Ключи — те же `key`, что у ползунков (`AsmrControlInfo.key`). Если ключ неизвестен, в `errors` попадает «unknown key `x`», а остальные изменения всё равно применяются. Ещё ядро принимает голый массив изменений и `{"key": k, "reset": true}`.
* Значения обрезаются по диапазону, такие помечаются `clamped`. У пресетов можно передать имя или индекс. `"reset"` (или `null`) у ребёнка плавно возвращает его на кривую макро, после чего снимается флаг `overridden`. У макро `reset` значит значение по умолчанию.
* **Плавные переходы**: непрерывные контролы идут к цели по smoothstep за `glide_s` секунд (по умолчанию 4, максимум 120, задаётся на весь патч или на отдельное изменение). Первый шаг делается сразу, поэтому изменение начинает звучать без задержки. Пресеты переключаются мгновенно. Время суток идёт коротким путём через полночь (23 → 2 проходит через 0, а не через полдень).
* Переходы живут в атомарных слотах: это без блокировок, работает по настенным часам, а двигают их аудиопоток каждый блок и читатели (`asmr_get_controls`, `asmr_get_state_json`), так что они доходят до цели и на паузе. Если пользователь трогает ползунок (`asmr_set_control`, `asmr_set_param`), переход на этом контроле отменяется.
* `moves` переставляет объекты с флагом MOVABLE сразу, в пределах ±40 м по горизонтали.
* `undo` — патч, который возвращает всё, чего коснулся исходный: макро получают прежние значения, дети прежнее значение, если были заданы явно, иначе `"reset"`; объекты возвращаются на прежние места.

## Промпт

Системный промпт генерируется из таблицы контролов (`describe()` в `prompt.rs`). В нём простыми физическими словами объяснён каждый ключ с единицами и опорными значениями (ветер 4 м/с — лёгкий бриз, дождь 4 мм/ч — ровный дождь, 3 часа ночи = 3). Дальше идут правила: менять только то, о чём просят; предпочитать макро; как понимать «чуть-чуть» (15–25 %), «сильнее» (30–50 %) и «намного» (×2); когда брать длинный `glide_s` («стихает», «постепенно»); правдоподобие (ночью мало птиц, гроза только с дождём). И восемь примеров: «поспокойнее», «3 a.m.», «гроза», «ночь, лёгкий дождь стихает», «как будто у водопада», «больше птиц слева», «верни реку как была», вопрос не по теме.

Схема инструмента тоже генерируется: `key` — enum всех ключей, `value` — число или enum имён пресетов плюс `"reset"`, обязательные поля `explanation` и `changes`. Диапазоны в схему не входят, потому что ядро всё равно обрезает значения, а не все провайдеры понимают `minimum`/`maximum` в строгом режиме. Тест `mock_provider_replies_apply` проверяет, что каждый пример из промпта — допустимый патч.

## Провайдеры (apps/macos/Sources/ASMRX3000/Prompt)

* `PromptProvider` — один метод `complete(PromptRequest) async throws -> PromptReply`. Запрос несёт текст, `system`, `context`, `state` (JSON) и схему, ответ — JSON входа инструмента.
* `Providers.current()` выбирает адаптер. `ASMR_PROMPT_PROVIDER=mock` включает `MockProvider` — ключевые правила, которые без сети дают патчи той же формы (используется в `--snapshot --prompt "…"`).
* **TypeSafe / System One (Jev)** — адаптер ещё не написан, потому что пока не прочитана документация HTTP API (docs.typesafe.ai/api.md). Особенность: System One отвечает типизированными суждениями (Choice / Score / вероятность «да»), а не свободным JSON. Возможная схема: «какие группы менять» как набор Noul, затем Score по направлению и силе для каждой группы на шкале и Choice для пресетов. Ядро в любом случае принимает тот же патч.
* Ключ API хранится в связке ключей (`Keychain.key(account:)`, служба `com.asmrx3000.prompt`). В репозиторий и логи он не попадает. Добавить ключ:

  ```bash
  security add-generic-password -U -s com.asmrx3000.prompt -a typesafe -w
  ```

## Интерфейс

Тонкая гравированная линия под сценой, плейсхолдер курсивом Cochin («Скажите, каким быть лесу…»). Enter отправляет запрос. Пока модель думает, под линией тихо мигает «слушаю…», потом появляется её однострочное объяснение. ⌘Z отменяет последний промпт (стек до 32 шагов). Ошибки показываются одной строкой: нет сети, нет ключа, ключ не принят, таймаут (10 с), непонятный ответ. Ползунки при этом работают как прежде. Если ядро пересоздаётся под новую частоту дискретизации, `AudioEngine` повторяет применённые патчи без переходов.

Цель по задержке — меньше 1,5 с до первого изменения. Ядро даёт первый шаг перехода сразу после ответа, так что задержку определяет сам вызов модели: нужна быстрая модель и кэш статического `system`.
