# ASMR X3000 — спецификация

> Единственная задача продукта — **физически правдоподобная симуляция звукового окружения** в реальном времени, с пространственным звуком и трекингом головы (AirPods).
> Первая цель: иконка в menu bar macOS → клик → «лес у реки» в наушниках.

---

## 1. Продукт

### 1.1 Что видит пользователь (MVP, macOS)
- Иконка в верхней панели (MenuBarExtra). Клик открывает поповер:
  - **Play / Pause** (большая кнопка), громкость.
  - Сцена: «Лес у реки» (пока одна).
  - Слайдеры «природы»: ветер, плотность птиц, время суток (рассвет → день → сумерки), близость реки.
  - Переключатель **Head tracking** (AirPods / AirPods Pro / Max / Beats с поддержкой).
  - Кнопка «Recenter» — обнулить направление «вперёд».
- Работает фоном, не крадёт фокус, ~0 % заметной нагрузки (цель: < 5 % одного ядра M-серии).

### 1.1.1 Поповер (визуальный стиль)
Ксилография «белой линией» в духе Бьюика с лёгкой ручной акварельной подкраской: свет прорезан в чёрной доске тонкими линиями, под линиями — бледные размывки (шалфей, серо-голубая вода, умбра). Шрифт Cochin. Чуть-чуть античности: слушатель — герма (бюст на столбе), у реки — упавшая колонна.
- **Сцена (Metal)**: лес у реки на круглом срезе земли, модели из Blender (`tools/blender/build_models.py` → `apps/macos/Resources/models.bin`), тени от солнца, штриховка идёт по форме. Объекты стоят там, где их держит движок; кроны гнутся по телеметрии `wind_field`; поющие птицы испускают сферические фронты, река — рябь на воде. Герма поворачивается вместе с головой (AirPods).
- **Выбор и перемещение**: клик по дереву, птице или реке; стрелки двигают по земле относительно камеры (по осям мира), ⇧↑/⇧↓ — высота, ⌥ — шаг 5 см вместо 25, tab — следующий объект, esc — снять выбор, пробел — play/pause. Перетаскивание — поворот камеры, колесо — приближение. Летящую птицу двигать нельзя.
- **Спектрограмма**: гравированные строки, толщина по энергии; наведение — частота, уровень, время; колесо — зум по частоте, клик — заморозить, двойной клик — сброс. Высоты птиц отмечены на правом краю.
- **Дорожки**: на каждом слайдере живая форма волны своего звука (`asmr_get_scope`); до ручки она «проявлена», дальше — бледный латентный след. Иконки — анимированные SVG-контуры без подписей.
- Play/pause, recenter, трекинг головы и выход — тихие иконки в углу сцены.

### 1.2 Платформы (по порядку)
1. **macOS** (MVP) — нативный Swift-шелл.
2. **Windows / Linux** — tray-приложение (Tauri), тот же движок.
3. **Chrome Extension** — движок в WASM внутри AudioWorklet (offscreen document, MV3).

Head tracking на старте только macOS (CoreMotion `CMHeadphoneMotionManager`). На других платформах — статический бинаурал, позже: веб-камера / IMU-гарнитуры.

### 1.3 Дальнейшая цель
Произвольные окружения по текстовому промпту: LLM генерирует **граф сцены** (геометрия, материалы, источники, их поведение), движок его исполняет. Поэтому всё, что ниже, строится вокруг явного, сериализуемого описания сцены, а не захардкоженного «леса».

## 2. Архитектура

```
┌──────────────── Shells ────────────────┐
│ macOS: SwiftUI MenuBarExtra + CoreMotion│
│ Win/Linux: Tauri tray                   │
│ Chrome: MV3 offscreen + AudioWorklet    │
└───────────────┬────────────────────────┘
                │ C ABI (UniFFI) / wasm-bindgen
┌───────────────▼──────────────────────────────────────────┐
│                 asmr-core  (Rust, no alloc в audio-потоке) │
│                                                            │
│  Scene graph ──► World sim ──► Sources ──► Propagation ──► │
│  (JSON/RON)      (время,      (генераторы   (физика       │
│                   погода,      звука)        распростр.)   │
│                   агенты)                        │         │
│                                                  ▼         │
│                        Ambisonics bus (3-й порядок, 16 ch) │
│                                                  │         │
│              head pose ──► rotation ──► binaural decode    │
│                                          (HRTF, SOFA)      │
└──────────────────────────────────────────────┬────────────┘
                                               ▼
                                     stereo → CoreAudio / WASAPI / ALSA / WebAudio
```

### 2.1 Почему так
- **Rust-ядро** — одна кодовая база для всех 4 платформ, детерминированный real-time без GC, компилируется и в нативный код, и в WASM.
- **Ambisonics как промежуточная шина.** Все источники кодируются в сферические гармоники (3-й порядок). Поворот головы = матрица поворота 16×16 над шиной — дёшево и не зависит от числа источников. Птиц может быть сотня, а цена трекинга головы константна. Декодирование в бинаурал — через HRTF (MagLS-декодер) из открытых SOFA-датасетов (SADIE II, HUTUBS); позже — персонализация.
- **Близкие, важные источники** (птица в 2 м, ручей у ног) можно рендерить напрямую через HRTF-свёртку в обход шины — лучшее разрешение там, где ухо его замечает.
- **Мы не используем Apple PHASE / системный Spatial Audio** для рендеринга — акустика наша, «с первых принципов». От Apple берём только позу головы. Важно: системный «Spatialize Stereo» должен быть выключен для нашего вывода, иначе будет двойная спатиализация (покажем подсказку в UI).

## 3. Слой 1 — генерация звука источников

Принцип: **физика там, где она известна точно; маленькие нейросети там, где физика слишком сложна (голос птицы)**. Всё должно работать в реальном времени на CPU и быть управляемым параметрами (а не просто проигрывать сэмплы).

### 3.1 Вода (река)
- **Физическая модель пузырьков** (резонанс Миннарта: f ≈ 3.26 м·Гц / r): звук текущей воды — это суперпозиция тысяч затухающих осцилляторов от схлопывающихся/образующихся пузырей с восходящим «chirp» (van den Doel, 2005). Параметры: скорость потока, турбулентность, распределение радиусов → разный характер «журчания».
- Источник не точечный, а **протяжённый (линейный)**: река = кривая в сцене, разбитая на N сегментов с некоррелированными генераторами. Даёт естественную «ширину».
- Позже: нейросетевой «доводчик» текстуры, обученный на реальных записях ручьёв (если физики будет не хватать по реализму).

### 3.2 Ветер и листва
- **Поле ветра**: стохастический процесс порывов (спектр фон Кармана / Орнштейн–Уленбек), пространственно коррелированный и перемещающийся по сцене с собственной скоростью — порыв слышно, как он «проходит» по лесу слева направо.
- **Листва**: гранулярный синтез — каждый «лист» = короткий шумовой импульс со спектром, зависящим от вида дерева (берёза/дуб/хвоя); плотность и энергия импульсов — функция локальной скорости ветра. Деревья — источники в пространстве, а не один стерео-луп.
- **Эоловы тона** (свист ветра на ветках, f = St·U/d, St ≈ 0.2) и низкочастотный «гул» ветра.

### 3.3 Птицы (главный ML-компонент)
Двухуровневая модель на каждый вид:
1. **Синтезатор (DDSP)** — differentiable DSP: гармонический осциллятор + фильтрованный шум, нейросеть предсказывает f0, амплитуды гармоник и спектр шума по кадрам. Модель ~100k–1M параметров, работает в реальном времени, звук полностью управляемый (высота, темп, громкость, «усилие»). Обучается на записях вида.
2. **Модель песни (синтаксис)** — маленький трансформер / RNN над токенами слогов: генерирует новые, но видоправдоподобные последовательности (у зяблика — фраза с «росчерком», у соловья — сложные репертуары).
3. **Поведенческий агент** (не нейросеть, а правила + стохастика): территория, перелёты (с Доплером), перекличка и ответ соседям, реакция на время суток (dawn chorus), ветер/дождь (птицы замолкают), «акустическая ниша» — виды избегают перекрытия по частоте/времени.

Стартовый набор видов (средняя полоса, лес у реки): зяблик, певчий дрозд, зарянка, большая синица, пеночка-весничка, иволга, кукушка, дятел (барабанная дробь — физическая модель), зимородок у воды. Ночью — соловей, сова.

### 3.4 Данные
| Что | Откуда | Внимание |
|---|---|---|
| Голоса птиц | xeno-canto (API v3), BirdCLEF (Kaggle) | лицензии per-recording, много CC BY-NC-SA → **проверить совместимость с коммерческим использованием**; храним манифест лицензий |
| Ветер, вода, лес | Freesound (фильтр CC0/CC BY) | шумные метаданные, нужна фильтрация |
| HRTF | SADIE II, HUTUBS (SOFA) | открытые лицензии |
| Импедансы грунта, поглощение | ISO 9613-1/-2, литература | — |

Пайплайн: скачать → сегментировать (BirdNET для детекции вида и вырезки чистых фрагментов) → денойз/отбор по SNR → признаки (f0 через CREPE/pYIN, loudness) → обучение DDSP. Обучение на M5 Max (PyTorch MPS), экспорт весов в собственный формат → инференс в Rust (простые слои, без тяжёлых рантаймов; для WASM — то же).

## 4. Слой 2 — движок распространения звука

Для каждой пары «источник → слушатель» (обновление ~50–100 Гц, интерполяция в аудио-потоке):

1. **Прямой путь**
   - Задержка распространения (c ≈ 343 м/с, зависит от температуры) → естественный **Доплер** у летящих птиц через переменную дробную задержку.
   - Геометрическое затухание 1/r (точечные) и 1/√r (линейные — река).
   - **Поглощение воздухом** ISO 9613-1 — частотно-зависимое (зависит от температуры и влажности; утренний влажный лес звучит иначе, чем сухой полдень).
   - **Направленность источника** (птица поёт в сторону — тише и темнее).
2. **Эффект земли** — интерференция прямого и отражённого от грунта луча с комплексным импедансом (модель Delany–Bazley: мох/трава/лесная подстилка/вода). Даёт характерный провал на низах у далёких источников.
3. **Окклюзия и дифракция** — стволы, рельеф, валуны. Луч к источнику перекрыт → дифракция по UTD/Маэкаве (частотно-зависимое затенение) вместо простого «приглушить».
4. **Рассеяние в лесу** — избыточное затухание от стволов и листвы (статистическая модель по плотности деревьев) + **реверберация леса**: не «комнатная», а многократное рассеяние на стволах. Ранние отражения — стохастический трассировщик лучей по стволам/рельефу; поздний хвост — FDN (feedback delay network), параметры которого выведены из геометрии (плотность стволов, средний свободный пробег).
5. **Турбулентность** — медленные флуктуации амплитуды/фазы далёких источников от ветра (то, почему далёкая кукушка «плывёт»).
6. **Кодирование в Ambisonics** с направлением прихода; ранние отражения — тоже со своими направлениями; диффузный хвост — декоррелированно по всей сфере.

Позже (для промпт-сцен с помещениями): волновые методы для низких частот (предрасчёт FDTD / ARD на GPU) + геометрические для высоких; порталы/двери; материалы со спектральным поглощением.

### 4.1 Real-time бюджет
- Аудио-поток: без аллокаций и блокировок, буфер 256–512 сэмплов @ 48 кГц.
- Физика путей — в отдельном «контрольном» потоке, передача параметров через lock-free очередь.
- Цель MVP: ≤ 64 активных источника, ≤ 5 % CPU на M-серии.

## 5. Граф сцены (база для будущих промптов)

Декларативный файл (RON/JSON), например:

```ron
Scene(
  name: "Forest by the river",
  environment: (temperature_c: 16, humidity: 0.8, time_of_day: 6.5, wind: (mean_ms: 2.0, gustiness: 0.4)),
  terrain: (ground: ForestFloor, heightmap: Procedural(seed: 42)),
  objects: [
    River(path: [(-60,0,8), (0,0,5), (60,0,9)], flow_ms: 0.8, turbulence: 0.5),
    Forest(region: Circle(center: (0,0,-20), r: 80), species: {Birch: 0.4, Spruce: 0.3, Oak: 0.3}, density_per_ha: 400),
  ],
  fauna: [
    Birds(species: Chaffinch, count: 4), Birds(species: SongThrush, count: 2), Birds(species: Robin, count: 3),
  ],
  listener: (position: (0, 1.7, 0), facing: (0,0,1)),
)
```

Промпт-сцены = LLM пишет такой файл (с валидацией схемы), движок исполняет. Поэтому любой новый тип источника добавляется как тип в графе.

## 6. Репозиторий (план)

```
asmrx3000/
  core/            Rust: asmr-core (dsp, sources, propagation, ambisonics, binaural, scene)
  ffi/             UniFFI-биндинги (Swift, позже Kotlin не нужен)
  apps/macos/      Xcode-проект: MenuBarExtra, CoreMotion, CoreAudio вывод
  apps/desktop/    Tauri (Win/Linux)
  apps/chrome/     MV3 extension + wasm
  ml/              Python: датасеты, обучение DDSP / моделей песни, экспорт весов
  assets/          HRTF (SOFA), веса моделей, сцены
  tools/           офлайн-рендер сцены в WAV (для тестов и сравнения)
```

Офлайн-рендерер `tools/render scene.ron --seconds 60 -o out.wav` — главный инструмент разработки: каждое изменение физики слушаем и сравниваем A/B.

## 7. Этапы

| # | Этап | Результат «готово» |
|---|---|---|
| **M0** | Скелет конвейера | Иконка в menu bar → ASCII-консоль → Play → река, ветер, 2 процедурные птицы в Ambisonics 3-го порядка → бинаурал (аналитический HRTF Brown–Duda) → AirPods; поворот головы стабилизирует сцену. Офлайн-рендерер, тесты ядра. |
| **M1** | Процедурный лес без ML | Река (пузырьки), ветер + листва по деревьям, простые параметрические птицы; прямой путь + Доплер + воздух + земля + FDN-реверб леса. Слайдеры в UI. Офлайн-рендерер. |
| **M2** | Нейро-птицы | Пайплайн данных, DDSP-модели 5–8 видов, модель песни, поведенческие агенты, dawn chorus. |
| **M3** | Геометрическая акустика | Окклюзия/дифракция, трассировка ранних отражений по стволам и рельефу, турбулентность. Граф сцены как файл. |
| **M4** | Другие платформы | Tauri (Win/Linux), Chrome Extension на WASM. |
| **M5** | Промпт-сцены | Текст → граф сцены (Claude API) → новые типы источников по мере надобности. |
